# 출타 신청 웹사이트 (leave-check)

부대 출타율 조정을 위한 휴가·외박·외출 신청 사이트입니다.
장병은 부대 공용 접속 코드를 입력한 뒤 달력에서 날짜를 골라 신청합니다. 관리자는 총원·종합기간·접속 코드·관리자 비밀번호를 설정하고, 신청 목록과 출타 명단을 관리합니다.
운영 중에 바꾸는 값은 모두 관리자 화면에서 바꾸므로 코드나 환경변수를 고칠 필요가 없습니다.

- 기술: Python 3.12+, Flask 3, SQLite(로컬) / Postgres(배포, Neon)
- 배포: Vercel (GitHub `develop` → 프리뷰, `main` → production)
- 개발 기록과 설계상 결정은 [Develop-memo.md](Develop-memo.md)에 있습니다.

## 주요 기능

### 접속 코드 (`/access`)
- 관리자가 접속 코드를 정하면, 코드를 입력한 사람만 신청 화면·관리자 화면·API를 쓸 수 있습니다. 입력한 기기는 30일 동안 다시 묻지 않습니다.
- **관리자도 예외가 아닙니다.** 관리자 화면(`/admin`)과 관리자 로그인도 접속 코드를 먼저 입력해야 열립니다. 관리자로 로그인해 있어도 코드가 바뀌면 새 코드를 다시 입력해야 합니다(코드를 바꾼 본인은 유지).
- 코드를 바꾸면 이미 접속한 사람도 모두 새 코드를 입력해야 합니다. 코드가 새었을 때 바로 바꾸세요.
- 코드가 설정되지 않으면 누구나 접속할 수 있습니다. 이때 관리자 화면에 붉은 경고가 나옵니다.

### 신청 화면 (`/`)
- **상단 바**: 오늘 날짜를 일력 모양으로 보여줍니다. PC(폭 1000px 이상)에서는 지금 접수 중인 외출/외박 주(수~화)의 날짜별 출타 인원을 띠로 보여주고, 날짜를 누르면 달력에서 그날을 고릅니다. 휴대폰에서는 띠를 숨깁니다.
- **출타 종류**: 휴가 · 외박 · 외출
  - 휴가·외박은 시작일과 종료일을 차례로 클릭하고, 외출은 하루만 고릅니다.
- **휴가**
  - 연가 · 보상 · 포상 · 위로 종류별로 일수를 입력하며, 합계가 신청 기간(일수)과 같아야 합니다.
  - 한 번에 최대 15일까지 신청할 수 있습니다.
  - 세부사유(선택, 100자)를 적을 수 있고, 관리자만 볼 수 있습니다.
- **외출/외박**
  - 외박은 1박 2일부터 3박 4일까지 신청할 수 있습니다.
  - 차수(1차 · 2차)를 고릅니다(선택).
  - 포상 · 공용에 체크할 수 있습니다.
  - 포상에 체크하면 포상 내용(예: 체력검정 특급 포상), 공용에 체크하면 공용 세부사항(예: 국군병원 외진)을 적는 칸이 나타납니다. 둘 다 체크하면 한 칸에 함께 적습니다. 관리자만 볼 수 있습니다.
- **달력**: 날짜마다 종류별 인원과 `계 n/최대`를 보여줍니다. 출타율을 넘은 날은 붉게, 접수하지 않는 날은 흐리게 표시합니다.
- **명단·취소**: 날짜를 누르면 그날 출타자 명단이 나옵니다. 신청할 때 정한 비밀번호로 본인 신청을 취소합니다.

### 관리자 화면 (`/admin`)
- 접속 코드를 입력한 뒤 관리자 비밀번호로 로그인합니다. 로그인은 12시간 뒤 풀립니다.
- 위에서부터 다음 순서로 있습니다.
  1. 부대 총원, 출타 명단 출력(A4, PDF 저장 가능 · 전체/휴가/외출·외박 · 기간 선택)
  2. 종합기간 설정과 "오늘 기준" 미리보기
  3. 월별 신청 목록: 그 달 출타율 초과 날짜, 신청 수정·삭제, 머리글을 눌러 정렬
  4. 접속 코드 설정·변경·해제, 관리자 비밀번호 변경
- 관리자 비밀번호를 바꾸면 다른 기기의 관리자 로그인은 모두 풀립니다. 처음에는 환경변수 `ADMIN_PASSWORD`가 초기 비밀번호입니다.

### 규칙
| 항목 | 내용 |
|---|---|
| 출타율 | 하루 기준 휴가 ≤ 총원의 20%, 휴가+외박+외출 ≤ 35% (소수점 버림). 공용 외출/외박은 제외 |
| 초과 시 | 신청은 받고, 신청 전후에 초과 사실을 안내 |
| 외출/외박 종합기간 | 수요일부터 7일간 출타분을 8일 전(화)부터 당일(수)까지 접수 |
| 휴가 종합기간 | 다음 달 휴가를 이번 달 20~28일에 접수 |
| 기준일 | 여러 날에 걸친 신청은 시작일 기준. 날짜는 한국 시간(KST)으로 판단 |
| 접속 코드 | 6~30자. 입력한 기기는 30일 유지 |
| 관리자 비밀번호 | 8~64자. 로그인은 12시간 유지 |

종합기간의 요일과 접수일은 관리자 화면에서 바꿀 수 있습니다.

## 파일 구성

```
app.py               Flask 서버 (DB, 검증, 출타율·종합기간 계산, 접속 코드·로그인, 보안 헤더, API)
templates/
  access.html        접속 코드 입력 화면
  index.html         신청 화면
  admin.html         관리자 화면
  print.html         인쇄용 출타 명단
static/base.css      공통 스타일 (색상 토큰, 다크 모드, 상단 바 일력)
tests/               pytest 테스트
vercel.json          Vercel 설정 (Flask)
.vercelignore        배포에서 제외할 파일
requirements.txt     실행에 필요한 패키지
requirements-dev.txt 테스트용 패키지 (pytest)
```

## 로컬 실행

```bash
pip install -r requirements.txt
ADMIN_PASSWORD='관리자비밀번호' python app.py
```

브라우저에서 http://localhost:5000 을 엽니다. 관리자 화면은 http://localhost:5000/admin 입니다.

- 데이터는 `leave.db`(SQLite)에 저장됩니다. 이 파일은 처음 실행할 때 자동으로 만들어지며 git에서 제외됩니다.
- 처음에는 접속 코드가 없어서 바로 열립니다. 관리자 화면에서 코드를 설정하면 그때부터 코드를 묻습니다.
- `ADMIN_PASSWORD`를 주지 않으면 로컬에서만 기본값 `1234`를 씁니다.
- 세션 키는 `SECRET_KEY` 환경변수를 쓰고, 없으면 `.secret_key` 파일을 자동으로 만듭니다(git 제외).
- 코드를 고치면서 자동으로 반영되게 하려면 `FLASK_DEBUG=1`을 함께 줍니다. 디버그 화면은 서버에서 코드를 실행할 수 있으므로 외부에 공개된 포트에서는 켜지 마세요.

### 환경변수

| 이름 | 로컬 | 배포 | 설명 |
|---|---|---|---|
| `ADMIN_PASSWORD` | 선택 (기본 `1234`) | **필수** | 관리자 **초기** 비밀번호. 관리자 화면에서 바꾸면 더 이상 쓰이지 않음 |
| `SECRET_KEY` | 선택 (`.secret_key` 자동 생성) | **필수** | 로그인 세션 서명 키 |
| `DATABASE_URL` | 선택 | **필수** (Neon 연결 시 자동) | 있으면 Postgres, 없으면 SQLite 사용 |
| `LEAVE_DB_PATH` | 선택 | - | SQLite 파일 경로 (기본 `leave.db`) |
| `FLASK_DEBUG` | 선택 | 쓰지 않음 | `1`이면 디버그 모드(코드 자동 반영·오류 화면) |

배포 환경(Vercel)에서는 `ADMIN_PASSWORD`나 `SECRET_KEY`가 없으면 앱이 시작하지 않습니다. 기본 비밀번호로 공개되는 것을 막기 위해서입니다.

### 잠겼을 때 복구

운영 DB(Neon)는 Neon 콘솔의 SQL Editor에서, 로컬은 `leave.db`에서 실행합니다.

| 상황 | 실행할 SQL | 결과 |
|---|---|---|
| 접속 코드를 잊음 (관리자도 못 들어감) | `DELETE FROM settings WHERE key = 'access';` | 접속 코드 해제. 관리자 화면에서 새로 설정 |
| 관리자 비밀번호를 잊음 | `DELETE FROM settings WHERE key = 'admin';` | 초기 비밀번호(`ADMIN_PASSWORD`)로 돌아감 |
| 연속 오입력으로 막힘 (기다리기 어려울 때) | `DELETE FROM attempts;` | 모든 오입력 기록 초기화 |

## 테스트

```bash
pip install -r requirements-dev.txt
python -m pytest
```

출타율, 종합기간(화·수요일 겹침 포함), 신청 검증, 비밀번호 취소, 관리자 권한, 세부사유·포상/공용 세부사항 비공개, 한국 시간 처리, 이전 DB 보정, 접속 코드(차단·변경·해제·관리자 포함), 관리자 비밀번호 변경, 보안(입력 타입·제어문자·요청 크기, 연속 오입력 제한, 다른 사이트 요청 차단, 보안 헤더·쿠키, XSS 이스케이프)을 확인합니다.
테스트는 임시 DB를 쓰므로 `leave.db`에 영향을 주지 않습니다.

Postgres에서도 같은 테스트를 돌릴 수 있습니다. 테스트가 테이블 내용을 지우므로 **테스트 전용 DB**만 쓰세요.

```bash
docker run -d --rm --name leave-pg -e POSTGRES_PASSWORD=pg -p 5432:5432 postgres:17-alpine
TEST_DATABASE_URL=postgresql://postgres:pg@localhost:5432/postgres python -m pytest
docker rm -f leave-pg
```

## 배포 (Vercel)

GitHub 저장소 `Ankwang032/leave-check`가 Vercel 프로젝트 `leave-check`에 연결되어 있습니다.

| 브랜치 | 배포 | 접속 |
|---|---|---|
| `develop` 등 `main` 외 브랜치 | 프리뷰 | Vercel 로그인한 사람만 (Deployment Protection) |
| `main` | production | **누구나** (접속 코드로 보호) |

- push하면 자동으로 배포됩니다. 브랜치마다 고정 주소가 생깁니다(예: `leave-check-git-develop-…vercel.app`).
- DB는 Neon Postgres(무료 플랜)를 씁니다. 프리뷰와 production이 **같은 DB**를 쓰므로 접속 코드·관리자 비밀번호·신청 데이터도 공유됩니다. 공개 전에 테스트 데이터를 지우세요.
- 테이블은 서버가 시작할 때 자동으로 만들어지고, 새 컬럼과 새 테이블도 자동으로 추가됩니다.

### production 공개 전 확인
1. 관리자 화면에서 **접속 코드를 설정**합니다. 프리뷰와 production이 같은 DB를 쓰므로 프리뷰에서 설정해도 됩니다. 코드를 아는 부대원은 명단을 볼 수 있으니 **부대 보안 규정**도 확인합니다.
2. `ADMIN_PASSWORD`와 `SECRET_KEY`를 Vercel의 **Production** 환경에도 추가합니다. 처음 로그인한 뒤 관리자 화면에서 **비밀번호를 바꿉니다**.
3. 프리뷰에서 다음을 확인합니다.
   - 글꼴(Pretendard)과 화면이 보안 헤더(CSP) 아래에서 정상으로 나오는지
   - 관리자 비밀번호를 6번 틀리면 "N분 뒤에 다시 시도하세요"가 나오는지 (Vercel의 접속 IP 처리 확인)
4. 프리뷰에서 넣은 테스트 신청을 관리자 화면에서 지웁니다.
5. `develop`을 `main`에 합칩니다.

## 보안·개인정보
- **인증·권한은 모두 서버에서 확인합니다.** 화면을 거치지 않고 API를 직접 불러도 같은 규칙이 적용됩니다.
- **접속 코드**: 코드가 있으면 코드를 입력한 사람만(관리자 포함) 명단·인원·API·관리자 화면에 접근합니다. 코드와 관리자 비밀번호, 신청 비밀번호는 모두 해시로 저장해서 관리자도 원래 값을 볼 수 없습니다.
- **열람 범위**: 세부사유와 포상 내용은 관리자만 볼 수 있고, 일반 API 응답에서는 빠집니다. 관리자로 로그인해 있어도 신청 화면에서 취소할 때는 신청 비밀번호가 필요합니다.
- **연속 오입력 제한**: 넘으면 그 시간 동안 막힙니다(429). 기록은 DB `attempts` 테이블에 두어 Vercel처럼 서버가 여러 개여도 함께 셉니다.

  | 대상 | 제한 |
  |---|---|
  | 관리자 비밀번호 (로그인·변경) | IP당 15분에 5번 |
  | 접속 코드 | IP당 10분에 10번 |
  | 신청 취소 비밀번호 | IP당 10분에 10번, 같은 신청은 모든 IP 합쳐 30분에 10번 |

- **입력 검증**: 모든 값의 타입과 길이를 서버에서 확인합니다. 이름·사유의 제어문자(글자 방향 뒤집기, 폭 없는 문자 등)는 거부하고, 요청 본문은 64KB로 제한합니다. DB 쿼리는 모두 자리표시자(`?`)를 써서 SQL Injection을 막습니다.
- **XSS 방지**: 서버 화면은 Jinja 자동 이스케이프를, 화면 스크립트는 `esc()`/`textContent`를 씁니다. CSP로 서버가 요청마다 넣은 스크립트(nonce)만 실행합니다.
- **요청·응답 보호**: 다른 사이트에서 보낸 변경 요청(`Sec-Fetch-Site: cross-site`)은 거부합니다. 세션 쿠키는 `HttpOnly`·`SameSite=Lax`(배포에서는 `Secure`)입니다. 다른 사이트가 화면을 틀(iframe)에 넣지 못하게 하고(`frame-ancestors 'none'`), 명단이 담긴 응답은 저장하지 않습니다(`Cache-Control: no-store`). 배포에서는 HSTS를 붙입니다.
- **검색 노출 차단**: 모든 응답에 `X-Robots-Tag: noindex`를 붙이고 `robots.txt`로 검색엔진 수집을 막습니다.
